# Data

Datasets are **not stored in Git** (they are large and have their own licences).
Every team member downloads them locally into `data/raw/` by following the steps below.
`data/raw/` and `data/processed/` are listed in `.gitignore`.

## Expected layout

```
data/
├── README.md                  (this file — committed)
├── raw/                       (git-ignored: original downloads, never modified)
│   ├── FullIJCNN2013.zip
│   ├── FullIJCNN2013/         GTSDB: 900 .ppm scene images + gt.txt + ReadMe.txt
│   ├── GTSRB_Final_Training_Images.zip
│   └── GTSRB/Final_Training/Images/00000 … 00042/
└── processed/                 (git-ignored: generated by our scripts, can be deleted and rebuilt)
```

Rule: **files in `raw/` are never edited by hand or by scripts.** Every transformation writes to `processed/`,
so the whole pipeline can be rebuilt from the original downloads.

## 1. GTSDB — German Traffic Sign Detection Benchmark (detection)

- Official page: https://benchmark.ini.rub.de/gtsdb_dataset.html
- Archive page: https://sid.erda.dk/public/archives/ff17dc924eba88d5d01a807357d6614c/published-archive.html
- File used: `FullIJCNN2013.zip` (all 900 images, 1360×800, PPM, with ground truth)

Annotation file `gt.txt`: one line per sign, fields separated by `;`:

```
filename;x_left;y_top;x_right;y_bottom;class_id
00000.ppm;774;411;815;446;11
```

Class IDs 0–42 are the same as in GTSRB (see `ReadMe.txt` inside the archive).
Images with no sign do not appear in `gt.txt`.

## 2. GTSRB — German Traffic Sign Recognition Benchmark (classification)

- Official page: https://benchmark.ini.rub.de/gtsrb_dataset.html
- Archive base: https://sid.erda.dk/public/archives/daaeac0d7ce1152aea9b61d9f1e19370/
- File used now: `GTSRB_Final_Training_Images.zip` (39,209 cropped sign images, 43 classes)
- Later (classifier evaluation): `GTSRB_Final_Test_Images.zip` + `GTSRB_Final_Test_GT.zip`

Each class folder contains `GT-000XX.csv` (fields separated by `;`).
Images are grouped in **tracks** of 30 images of the same physical sign: train/validation splits must keep
a whole track on the same side, otherwise validation accuracy is artificially high.

## Download (Windows PowerShell, from the repository root)

```powershell
New-Item -ItemType Directory -Force data\raw | Out-Null

curl.exe -L -o data\raw\FullIJCNN2013.zip https://sid.erda.dk/public/archives/ff17dc924eba88d5d01a807357d6614c/FullIJCNN2013.zip
curl.exe -L -o data\raw\GTSRB_Final_Training_Images.zip https://sid.erda.dk/public/archives/daaeac0d7ce1152aea9b61d9f1e19370/GTSRB_Final_Training_Images.zip

tar -xf data\raw\FullIJCNN2013.zip -C data\raw
tar -xf data\raw\GTSRB_Final_Training_Images.zip -C data\raw
```

If a direct link fails, open the archive page in a browser and download the file manually into `data\raw\`.

## Verification

```powershell
(Get-ChildItem data\raw\FullIJCNN2013\*.ppm).Count                                # expected: 900
(Get-Content data\raw\FullIJCNN2013\gt.txt).Count                                # expected: 1206
(Get-ChildItem data\raw\GTSRB\Final_Training\Images -Recurse -Filter *.ppm).Count  # expected: 39209
```
